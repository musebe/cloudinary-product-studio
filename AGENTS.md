# Project conventions

- Work in this project only. Other article projects, especially the paused Jev project, stay untouched.
- Article: Keep AI Product Images Consistent With Vue and Cloudinary.
- Use Vue 3 Composition API, TypeScript, and `<script setup lang="ts">`. Follow the installed `vue-best-practices` and `vue-testing-best-practices` skills from vuejs-ai/skills.
- Use current official Nuxt and Cloudinary documentation. Keep credentials in server-only runtime configuration.
- Keep the app focused on product-reference selection, controlled scene variation, and a visible comparison. Editorial metadata belongs in docs.
- Product consistency is a goal, not an AI guarantee. Do not invent automatic scores, semantic analysis, provenance, approval, or benchmark results.
- Published Cloudinary example assets must be labeled as examples, not new generations from this product environment.
- Never run paid generation, background replacement, analysis, or a live upload without a separately approved bounded budget.
- Previewing a plan must not request an AI transformation URL or trigger a provider operation.
- Keep approval bound to the candidate and reference. A browser-only review is not a server-enforced publication gate or durable audit store.
- Use props down, typed events up, computed derived state, focused composables, and accessible native controls.
- Validate and commit each completed checkpoint. Never commit `.env`, `.env.local`, credentials, or test artifacts.
- Record verified implementation steps and limitations while building. Write the article after the demo is proven. The final handoff stays within one or two pages.
