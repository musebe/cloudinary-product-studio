# Product Studio

A focused Vue and Cloudinary demo for reference-led product imagery. Compare a product photograph with a saved AI example, plan a controlled scene change, and record a human review of the product's shape, color, and details.

**Current checkpoint:** working saved comparison and scene planning. Live uploads, generation, and server-side review persistence are not implemented yet.

## Run locally

Use Node.js 24 and pnpm 10:

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

Open [Product Studio](http://localhost:3004). If `.env.local` already exists, keep it instead of copying the template over it.

The saved demo needs no credentials. Both example images are included in `public/demo`, so the first load does not contact Cloudinary or generate an image.

## Try the demo

1. Compare the original teapot photo with the saved watercolor result. Use **Enlarge image comparison** to inspect each image.
2. Review the three product checks. **Accept candidate** becomes available only when all three are checked; **Needs changes** is always available.
3. Download the evidence JSON. It contains the source and candidate identities, file hashes, provenance, and the current local review.
4. Select a scene and choose **Preview scene request**. This shows the fixed reference, prompt, model, and seed without requesting an image.
5. Optionally enable **Use Cloudinary delivery**. This loads the published examples through the Cloudinary Vue SDK, with no transformation chain. A failed request falls back to the packaged files. Switching delivery resets the review; review/download stay disabled until you return to the hash-checked saved files, because remote bytes have not been verified.

The watercolor is a **published Cloudinary documentation example**, not a result generated by this app and not an output of one of the three scene presets. Its changed finish makes it useful for demonstrating why reference-guided results still need inspection. It is not automatically marked as passing.

## Configuration

These variables are private Nuxt runtime configuration. Do not use a `NUXT_PUBLIC_` prefix for credentials.

| Variable                     | Purpose                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `NUXT_CLOUDINARY_CLOUD_NAME` | Product environment for future live operations                                        |
| `NUXT_CLOUDINARY_API_KEY`    | Server-side Cloudinary API authentication                                             |
| `NUXT_CLOUDINARY_API_SECRET` | Server-side Cloudinary API secret                                                     |
| `NUXT_DEMO_SESSION_SECRET`   | A fresh random secret of at least 32 bytes for future session support                 |
| `NUXT_ENABLE_LIVE_UPLOADS`   | Reserved; keep `false` until upload support is implemented                            |
| `NUXT_ENABLE_GENERATION`     | Reserved; keep `false` until generation support and spending controls are implemented |

`pnpm dev` explicitly loads `.env.local`. Restart the development server after changing it. The health endpoint reports whether credentials are supplied, not whether they have been verified with Cloudinary. Setting a reserved flag to `true` does not activate an unimplemented feature.

## Verify

```bash
pnpm check
pnpm exec playwright install chromium
pnpm test:e2e
```

`check` runs formatting, linting, type checking, unit/component tests, and the production build. Browser tests use their own development server on port 3104 and an isolated `.nuxt-e2e` build directory; leave that port available. They do not stop the regular development server.

```bash
curl http://localhost:3004/api/health
```

`POST /api/generate` returns JSON with HTTP 501 and performs no provider operation. Browser tests block/mock external image delivery rather than making generation requests.


## Boundaries

- A reference and a fixed seed do not guarantee product identity. No automatic consistency score is calculated.
- Reviews are browser-only attestations. Changing a check invalidates the decision; refreshing clears it. They are not durable audit records or a publication gate.
- Previewing a scene does not edit the saved candidate or create a delivery URL for a new output.
- Live operations need account capability checks and a separately approved, bounded generation budget.
- No database, paid analysis, background replacement, or image generation is required for the saved demo.

## Example sources

The source and watercolor result come from [Cloudinary's Image Generation documentation](https://cloudinary.com/documentation/image_generation_addon#let_cloudinary_choose_the_edit_model). The original published URLs, dimensions, byte counts, SHA-256 hashes, and prompt are recorded in `shared/studio/example.ts` and checked by tests. They are attributed examples, not original artwork created by this project; use your own authorized product assets for a real catalog.
